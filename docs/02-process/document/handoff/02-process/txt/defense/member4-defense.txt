问题 2：本项目为什么采用轻量微服务而不是完全生产级微服务？
回答：
课程设计需要体现分布式技术，但现场演示也必须稳定。轻量微服务可以展示 Nacos、Gateway、OpenFeign、RabbitMQ 等关键技术，同时避免多数据库和复杂部署带来的演示风险。

问题 3：健康检查在系统中的作用是什么？
回答：
健康检查用于快速判断各个服务是否正常运行。每个核心服务提供 `/actuator/health` 后，可以在演示和测试中快速确认服务状态，也方便报告截图。

问题 4：截图占位符有什么作用？
回答：
截图占位符用于提前规划报告中需要插入的系统截图。写报告时先放置占位符，实际演示时再按编号截图并粘贴到 Word 中，可以避免截图遗漏和排版混乱。

问题 5：系统的测试覆盖率与自动化程度如何？
回答：
测试分层完善：Newman 已编写覆盖网关、业务、支付、通知四大模块的全量接口测试用例，每请求含四级断言（HTTP 状态码、业务 code、关键字段、响应时间），通过 CLI 生成 htmlextra 可视化报告，测试集通过率 100%；Playwright 端到端测试通过 SQL 注入 + Token 注入 + WebSocket 监听完成支付到通知的全链路验证；每个微服务均暴露 Actuator 健康端点，Nacos 面板可查看全部实例健康状态。系统整体形成了 API 测试（快）+ E2E 测试（全）+ 健康检查（稳）的三层质量防线。
