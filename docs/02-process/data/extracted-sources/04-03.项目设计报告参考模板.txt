摘 要
本项目基于Spring Boot和Spring Cloud技术，设计并实现了一个分布式电商系统。系统采用前后端分离和微服务架构，涵盖用户管理、商品管理、订单管理、内容管理、支付、邮件通知等核心功能模块。通过引入MyBatis-Plus简化数据持久层开发，利用MySQL进行数据存储，借助Nacos实现服务注册与发现，提升了系统的可扩展性和高可用性。项目还集成了Apifox等接口测试工具，保障了各模块间的高效联调与稳定运行。系统结构清晰，功能完善，能够满足现代电商平台的基本业务需求，为后续功能扩展和系统优化提供了良好基础。

关键词：Spring Boot；Spring Cloud；微服务；电商系统；MyBatis-Plus
springboot-buy
Abstract
This project is based on Spring Boot and Spring Cloud technologies, and designs and implements a distributed e-commerce system. The system adopts a front-end and back-end separation as well as a microservices architecture, covering core functional modules such as user management, product management, order management, content management, payment, and email notifications. MyBatis-Plus is introduced to simplify the development of the data persistence layer, while MySQL is used for data storage. Nacos is utilized for service registration and discovery, enhancing the system’s scalability and high availability. The project also integrates interface testing tools such as Apifox to ensure efficient integration and stable operation between modules. The system features a clear structure and comprehensive functions, meeting the basic business needs of modern e-commerce platforms and providing a solid foundation for future functional expansion and system optimization.

Keywords: Spring Boot; Spring Cloud; Microservices; E-commerce System; MyBatis-PlusX

引言
项目目的
本项目旨在开发一个基于Spring Boot的分布式电商系统，实现商品管理、订单管理、用户管理、内容管理、支付、邮件通知等核心功能。通过模块化设计和微服务架构，提升系统的可扩展性、可维护性和高可用性，满足实际电商业务的需求。项目目标包括：
提供完整的电商业务流程支持，包括商品浏览、下单、支付、订单跟踪等。
实现用户、商品、订单、内容等数据的分布式管理，提升系统性能和并发处理能力。
通过模块解耦，便于后续功能扩展和系统维护。
集成邮件通知、支付接口等第三方服务，提升用户体验。
采用主流技术栈和开发规范，提升项目的学习和实践价值。

相关技术概述
后端开发框架
Spring Boot
Spring Boot 是一个基于 Spring 框架的快速开发框架，旨在简化 Spring 应用的初始搭建以及开发过程。它通过自动配置、内嵌服务器、简化的依赖管理等特性，大大提升了开发效率，降低了项目的配置复杂度。在本大作业中，Spring Boot 作为整个分布式电商系统的基础框架，承担了以下核心作用：
快速搭建微服务模块：本项目的各个子模块（如用户服务、订单服务、内容管理服务、支付服务等）均基于 Spring Boot 独立开发，实现了服务的高内聚、低耦合。
简化配置与部署：通过 application.yml、自动装配等机制，极大简化了项目的配置和环境切换，便于本地开发、测试和线上部署。
集成主流中间件与第三方服务：Spring Boot 便于与 MyBatis-Plus、Swagger、邮件服务、支付接口等常用组件和第三方服务集成，提升了系统的功能扩展性。
统一异常处理与日志管理：利用 Spring Boot 的全局异常处理和日志管理机制，提升了系统的健壮性和可维护性。
Spring Cloud
Spring Cloud 是一套基于 Spring Boot 的分布式系统开发工具集，专注于为微服务架构提供完整的解决方案。它集成了服务注册与发现、配置管理、负载均衡、断路器、消息总线等功能，极大地简化了分布式系统的开发和运维。在本大作业中，Spring Cloud 的作用主要体现在以下几个方面：
服务注册与发现：通过集成 Nacos 等注册中心，实现各个微服务（如用户服务、订单服务、支付服务等）的自动注册与发现，便于服务间的通信和动态扩展。
分布式配置管理：利用 Spring Cloud Config 或 Nacos 配置中心，实现多环境下的统一配置管理，支持配置的动态刷新，提升系统的灵活性和可维护性。
负载均衡与容错：通过 Ribbon、Feign 等组件，实现服务间的负载均衡和远程调用，提升系统的高可用性和扩展能力。
服务链路追踪与监控：集成 Spring Cloud Sleuth、Zipkin 等工具，对分布式系统中的服务调用链路进行追踪和监控，便于问题定位和性能优化。
消息驱动与异步通信：通过 Spring Cloud Stream 等组件，实现服务间的异步消息通信，提升系统的解耦性和响应速度。
数据持久层
MyBatis-Plus
MyBatis-Plus 是在 MyBatis 基础上扩展的增强型 ORM 框架，简化了数据库操作，提升了开发效率。它提供了丰富的 CRUD 接口、条件构造器、分页插件等功能，极大减少了重复代码。在本大作业中，MyBatis-Plus 主要用于各个微服务模块（如用户、订单、内容等）的数据持久化操作，实现了对数据库表的高效增删改查。通过自动生成的 Mapper 接口和 XML 映射文件，开发者可以专注于业务逻辑的实现，无需手写大量 SQL 语句。同时，MyBatis-Plus 的分页和条件查询功能也为系统的数据展示和检索提供了便利。
MySQL
MySQL 是当前主流的开源关系型数据库管理系统，具有高性能、高可靠性和易用性等优点。在本大作业中，MySQL 作为各个微服务的数据存储后端，负责存储用户信息、商品信息、订单数据、内容数据等核心业务数据。通过与 MyBatis-Plus 的无缝集成，实现了数据的高效读写和事务管理。MySQL 的表结构设计合理，支持多表关联、索引优化等特性，保障了系统在高并发场景下的数据一致性和访问效率。
服务治理与配置中心
Nacos

Nacos 作为分布式系统的服务注册与发现组件，能够动态管理各个微服务的注册与状态。如图所示，buy-cms、buy-user、buy-pay、buy-email、buy-orders、buy-manager 等六个核心微服务均已成功注册到 Nacos，并处于健康运行状态。每个服务都属于 DEFAULT_GROUP 分组，当前每个服务有一个实例，且未开启保护阈值。通过 Nacos 的可视化界面，开发者可以方便地对服务进行管理、监控和维护，极大提升了系统的可用性和运维效率。这也体现了本项目采用 Spring Cloud 微服务架构的实际落地效果。
接口测试与调试工具
Apifox
Apifox 是一款集接口文档、接口调试、自动化测试和 Mock 数据于一体的专业 API 工具。它支持 OpenAPI、Swagger 等主流接口规范，能够帮助开发者高效地进行接口的设计、调试与测试。在本大作业中，Apifox 主要用于各微服务接口的联调与验证。通过导入项目的接口文档，开发者可以方便地进行接口请求测试、参数校验、响应结果查看等操作，大大提升了开发和测试效率，保障了系统各模块间的接口兼容性和稳定性。

系统分析设计
需求分析
本项目旨在开发一个分布式电商系统，满足现代电商平台的基本业务需求。通过对实际业务场景的调研与分析，系统需求主要分为功能性需求和非功能性需求两大类。
3.1.1 功能性需求
用户管理
用户注册、登录、信息修改、密码找回等基本功能。
支持用户角色区分（如普通用户、管理员）。
商品管理
商品的添加、编辑、删除、上架、下架等操作。
商品分类、标签管理，支持多条件查询和筛选。
订单管理
用户下单、订单支付、订单查询、订单取消等功能。
支持订单状态跟踪（如待支付、已支付、已发货、已完成、已取消）。
内容管理
支持发布公告、文章、活动等内容，便于平台信息传递。
内容的增删改查及分类管理。
支付功能
集成主流支付方式（如支付宝），实现订单在线支付。
支付状态回调与订单状态联动。
邮件通知
用户注册、下单、支付等关键操作后，自动发送邮件通知。
支持邮件模板管理。
接口管理与测试
提供标准化的RESTful API接口，便于前后端分离开发。
支持接口文档自动生成与在线调试。
3.1.2 非功能性需求
系统性能
支持高并发访问，保证系统响应速度和稳定性。
数据库读写分离，提升数据处理能力。
安全性
用户数据加密存储，防止信息泄露。
接口权限校验，防止未授权访问。
可扩展性
采用微服务架构，便于后续功能扩展和模块独立部署。
可维护性
代码结构清晰，注释规范，便于后期维护和升级。
高可用性
关键服务支持集群部署，提升系统容错能力。
易用性
提供友好的用户界面和操作流程，提升用户体验。

User表用于存储平台用户的基本信息，支持唯一用户名和邮箱，包含用户的联系方式、状态等字段。Order表用于记录用户的订单信息，包含订单编号、金额、状态、收货信息等，并通过user_id与User表关联，实现用户与订单的一对多关系。这两张表是电商系统的核心数据表，支撑了用户管理和订单管理的主要业务流程。

-- 创建用户表
CREATE TABLE IF NOT EXISTS `user` (
    `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `username` varchar(50) NOT NULL COMMENT '用户名',
    `password` varchar(100) NOT NULL COMMENT '密码',
    `email` varchar(100) NOT NULL COMMENT '邮箱',
    `phone` varchar(20) DEFAULT NULL COMMENT '手机号',
    `real_name` varchar(50) DEFAULT NULL COMMENT '真实姓名',
    `gender` tinyint(1) DEFAULT '0' COMMENT '性别：0-未知，1-男，2-女',
    `birthday` date DEFAULT NULL COMMENT '生日',
    `address` varchar(255) DEFAULT NULL COMMENT '地址',
    `status` tinyint(1) DEFAULT '1' COMMENT '状态：0-禁用，1-正常',
    `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_username` (`username`),
    UNIQUE KEY `uk_email` (`email`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

-- 创建订单表
CREATE TABLE IF NOT EXISTS `t_order` (
    `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '订单ID',
    `user_id` bigint(20) NOT NULL COMMENT '用户ID',
    `order_no` varchar(64) NOT NULL COMMENT '订单编号',
    `total_amount` decimal(10,2) NOT NULL COMMENT '订单总金额',
    `status` tinyint(4) NOT NULL DEFAULT '0' COMMENT '订单状态：0-待支付，1-已支付，2-已取消，3-已退款',
    `address` varchar(255) NOT NULL COMMENT '收货地址',
    `receiver_name` varchar(64) NOT NULL COMMENT '收货人姓名',
    `receiver_phone` varchar(20) NOT NULL COMMENT '收货人电话',
    `remark` varchar(255) DEFAULT NULL COMMENT '订单备注',
    `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_order_no` (`order_no`),
    KEY `idx_user_id` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单表';
