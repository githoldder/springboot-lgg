# Sprint 08 PRD: 多角色履约、权限划分与运营治理

Last Updated: 2026-07-17

## 大目标

在已有订单履约基础上，补齐管理员、商家、骑手、用户的权限边界，复用 RuoYi 的系统管理、角色菜单、日志和监控能力，让系统从“能下单”推进到“能多人协作运营”。

## 范围边界

- 不做三套完整小程序端，先做角色权限和骑手轻量任务页。
- 不新增独立商家 App，优先复用管理端 RuoYi 权限体系。
- 不重构完整认证系统，优先延续 Sprint06 的 token/openid 绑定和 RuoYi 权限。
- 系统监控优先复用现有 `views/monitor`，只补业务说明和入口。

## 验收标准

- admin、merchant、rider 登录后菜单与 API 权限不同。
- 骑手只能看到自己的配送任务，并能更新配送状态。
- 商家能操作订单、商品、售后、评价，不暴露系统配置。
- 管理端能查看 RuoYi 监控与微服务健康入口。
- 首页或报表可展示售后率、评价率、用券率。
